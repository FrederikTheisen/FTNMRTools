etaXY: nico_nnh_tr_noSE
======================

Keep eta_xy.py, eta_xy_proc.com, eta_xy_analyze.com and relax_tools.py together.
No script runs just by being copied. The old relaxation scripts are unchanged.
Requirements: Python 3.8+, the existing NMRPipe/data_xtr environment, and gnuplot
with pdfcairo. The Python code uses its standard library only.

ACQUISITION AND EQUATION

The reviewed pulse program cycles l5 through four pathways inside each
States-TPPI component. Planes 1/4 retain their initial operator (auto_A/auto_B);
planes 2/3 transfer between the operators (cross_AB/cross_BA). The preparation
branches select 1/2 versus 3/4; the detection branches select 1/3 versus 2/4.
The pulse code, initial counter and acquisition mode are validated before use.
Unknown programs, changed pathway/timing code and TopSpin split copies are
rejected rather than assigned the same formula by name alone.

    q = sqrt(I2 I3 / (I1 I4))
    |etaXY| = atanh(q) / T

T is D20, already the TOTAL effective transverse relaxation time. Do not
multiply it by two or treat it as d24. The two d24 delays subtract gradient and
pulse durations, including the pulse program's 0.637 correction for each
bounding 90-degree pulse. This is the sequence's effective-time convention,
not an independently calibrated timing measurement. Current reviewed examples
use D20 = 0.05 s.

The four-pathway product gives the magnitude of eta, not its sign. Columns
therefore explicitly say eta_xy_abs_s-1 and eta_xy_abs_error_s-1. The method is
symmetrical reconversion, not an exponential fit:
Pelupessy et al., J. Magn. Reson. 161 (2003), 258-264.
https://doi.org/10.1016/S1090-7807(02)00190-8
The transverse product relation is also Eq. 1 of Pelupessy et al., J. Chem.
Phys. 126 (2007), 134508: https://doi.org/10.1063/1.2715583

ONE ACQUISITION, ONE PEAK LIST

Prefer the original packed acquisition over creating new TopSpin expnos.
For example, May 12 2025 hANP32a 50 mM NaCl experiment 6 contains all four
pathways. Its existing split 10007/10008/10009/10010 datasets correspond to
planes 1/2/3/4; this was checked by comparing every raw FID record read-only.
No reprocessing is needed merely to inspect the acquisition:

    python3 /path/to/eta_xy.py inspect --experiment /path/to/collection/6

When ready to process, run from the ORIGINAL experiment:

    tcsh /path/to/eta_xy_proc.com

Output stays in a dedicated eta_xy_processed/ directory. Whole Bruker FID
records are deinterleaved into temporary files, converted as ordinary 2D
States-TPPI spectra, and processed with one common recipe. No new Bruker
experiment numbers are created. No Rance-Kay shuffling macro is applied:
this pulse program uses States-TPPI, unlike the gradient-selected relaxation
template. The 15N Fourier step applies its required sign alternation once.
The two readout branches have opposite 15N frequency directions: planes 2/4
therefore require FT -neg in addition to -alt. This decodes the acquisition;
all four planes still receive the same phase/window/baseline settings. The
direction correction was confirmed on actual May 12 data: before correction
the 2/4 peaks were mirrored, afterward all four peak positions aligned. An
old processing record without this correction is rejected by the analyzer.

Direct conversion parameters come from acqus/acqu2s. Processing retains the
shared template's SOL, SP .4/.98/2/.5, left-half proton extraction and
POLY -auto -ord 4 choices. Review/tune common H/N phases in eta_xy_proc.com;
zero is an editable starting setting, not a validated phase for every dataset.
No automatic phase correction, per-plane normalization or sign repair occurs.
The raw format currently supported is the observed int32 DQD/States-TPPI
layout, with Bruker 1024-byte row padding. Other formats fail explicitly.

Processing writes:
    eta_xy_processed/planes/plane_01.ft2 ... plane_04.ft2
    eta_xy_processed/m.ft3        four-plane NMRPipe stack
    eta_xy_processed/proc.ucsf    the same series for inspection
    eta_xy_processed/vEstNoise.txt   four noise SDs from specStat.com
    eta_xy_processed/processing.txt  common processing settings

Export ONE assigned peak list from the well-phased first reference plane
(plane_01.ft2). A 2D list from this plane or a 3D list from the stack is
accepted. Intensities in that exported list are ignored: data_xtr samples the
same coordinates in all four planes. Overlaps are retained and marked;
duplicate assignments at different coordinates are kept as separate peaks.

    tcsh /path/to/eta_xy_analyze.com

Or use explicit paths without copying scripts into the experiment:

    python3 /path/to/eta_xy.py analyze --experiment /path/to/collection/6 \
        --peaks /path/to/etaXY.list --data /path/to/eta_xy_processed/m.ft3 \
        --noise /path/to/eta_xy_processed/vEstNoise.txt --output-dir /path/to/output

OUTPUT AND UNCERTAINTY

Three user-facing files: <prefix>.pdf, <prefix>_numbers.csv, <prefix>_support.zip.
The CSV has one row per peak, with eta/error, overlap and quality flags,
coordinates, q/error and the four measured intensities. Shared provenance,
T, plane roles and noise SDs occur once as trailing # metadata lines. For
pandas use read_csv(filename, comment='#'); ordinary csv readers should skip
comment RECORDS after CSV parsing. No analysis IDs, hashes or code fingerprints
are added. The PDF shows the rate and product-ratio overviews. The support ZIP
keeps the extraction tags/mapping, original peak list, measured intensities,
noise vector, acquisition parameters, pulse program and plotting records.
It also includes processing.txt when available. Optional coordinates_source,
common_coordinate_shift_ppm and purpose peak-list comments carry through to
the numbers footer, for example when using registered coordinates for a test.

Noise is per-plane SD in the SAME units as extracted heights. Error propagation
assumes independent Gaussian plane noise and fixed peak positions/time:
    sigma_q = q/2 * sqrt(sum((sigma_i/I_i)^2))
    sigma_eta = sigma_q / (T * (1-q^2))
Overlap, baseline/phase errors, coordinate uncertainty and time calibration
are not included in these uncertainties. Low auto/cross SNR (<3) and q +/-
2 sigma_q reaching 0 or 1 are review flags: first-order uncertainties may be
unreliable there. Overlaps/low SNR do not silently disappear from the table.
Zero intensities, inconsistent product signs and q outside (0,1) receive blank
eta/error fields and explicit invalid flags. Ratios are never clipped into
the allowed domain, and a negative product ratio is not repaired with abs().
Two negative products give a positive ratio and are allowed: a consistent sign
in one preparation/detection channel cancels in symmetrical reconversion.

Existing reports are backed up. Every command and pipeline stage is checked;
publication uses the shared lock, temporary staging and rollback machinery.
To recompute an analysis from saved intensities without spectral extraction,
unpack the support archive into a temporary directory and use --extracted
extracted_ids.out with --peaks original_peak_list.list, --noise vEstNoise.txt
and --experiment pointing to the unpacked acquisition files. The same three
outputs are generated; only gnuplot is invoked. No rlx_dfit call is made.
Keep the accompanying peaks.list beside extracted_ids.out: its identifiers and
coordinates are checked against the original peak list. The extraction's short
comment footer retains the original source/experiment/time when an archive is
unpacked somewhere else.

VERIFICATION WITHOUT DATA PROCESSING

    PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover \
        -s relax/tests -p test_eta_xy.py -v

Tests use synthetic acquisition/data files and stub external commands. Writing
the scripts and running these tests does not process experimental spectra.
