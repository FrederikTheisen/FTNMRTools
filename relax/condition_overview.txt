CONDITION OVERVIEWS AND SAVED-REPORT REFRESH

Keep condition_overview.py beside relax_tools.py. Python 3.8+ and gnuplot
(pdfcairo) are required. No NMRPipe, spectrum extraction or fitting executable
is invoked. The command does not discover/pick peaks, repair FIDs or average
acquisitions. Original experiment scripts, raw/processed spectra and CCPN
projects are never changed. The protected 211@950 subtree is rejected.

USAGE

    python3 /path/to/FTNMRTools/relax/condition_overview.py \
        --project-root /path/to/Electrostatics \
        --data-root /path/to/nmrdata \
        --catalog /path/to/master_acquisitions.csv \
        --fid-inventory /path/to/experiment_inventory.csv \
        --r1-qc /path/to/dataset_status.csv \
        --qc-decisions /path/to/reviewed_findings.json \
        --refresh-reports

Use --dry-run first for a read-only disposition summary. Omit --refresh-reports
to regenerate only the condition overviews from existing numbers files. The
three QC arguments are optional; unavailable acquisition QC is not_assessed.

The catalog is the reviewed master acquisition CSV already used by the
Electrostatics delivery. Only analysed R1, R1rho and HetNOE entries are selected.
It explicitly identifies each current report directory, avoiding directory-wide
searches that could count archived/pilot/diagnostic reruns as extra acquisitions.
Each selected directory must have exactly one *_numbers.csv. Duplicate source
acquisitions, conflicting source/sequence metadata and unsafe destinations fail
before publication. CPMG and other incompatible observables are not included.

GROUPING AND QUALITY

Group keys are protein/construct, observable, NaCl concentration, nominal
temperature, field, and any explicitly recorded additive condition. Historical
folder labels and controller TE are never used to establish a condition. The
master's per-experiment nominal temperature is used rather than a collection's
multi-temperature annotation. Explicitly provisional temperature assignments,
unconfirmed salt/temperature/construct or pending condition review are held out
of confirmed groups and listed in the delivery index.

The reviewed findings JSON's known_strong_growth_experiments list and explicit
exclusions, plus investigator exclude_from_primary_analysis=true decisions,
exclude acquisitions. Automatic metrics alone do not create new exclusions.
Minor/unresolved FID flags are review; missing QC is not_assessed. A saved
screen without major flags is labelled screened_no_major_flags, not clean.
Retained-range R1 screening is used so omitted raw tails are not confused with
artefacts in the analysed range. Review flags do not imply a confirmed cause.

Sequence families are displayed rather than silently pooled or averaged.
R1rho spin-lock strength and offset are included where already documented;
otherwise strength is unknown. A failed exponential goodness-of-fit test is a
residue-level flag, not automatic evidence of acquisition corruption.

TSV LAYOUT

Each condition gets overview.tsv at its existing condition-directory level.
It is an AUTOMATICALLY GENERATED OUTPUT: do not edit its values or insert review
comments. Regeneration replaces it, retaining a backup. A notice at the top
states this; persistent comments belong in condition-reviews.tsv (see below).

Condition and units comments precede SIX compact header rows:
    source: exactly one collection/expno per acquisition block
    pulse / protocol: actual PULPROG; available R1rho spin-lock settings
    delays used: "all delays used" or e.g. "1 ms delay omitted"
    noise / median first-plane height: per-plane noise percentages and reference
    acquisition QC: saved screen status and any user assessment/comment
    fit assessment: valid/flagged peak counts and saved dataset conclusion

The column header then introduces one residue column and a block per acquisition:
    R1, error, overlap, reduced_chi2, flags
Use R1rho or hetNOE for those observables. HetNOE omits reduced_chi2 and retains
signed ratios. Parameter/error headings repeat without acq01 prefixes; identify
blocks by position and the source row. These are intentionally spreadsheet-style
multi-row headers, so a plain DictReader with duplicate names is unsuitable.
Use csv.reader or construct column keys from source plus parameter heading.
Detailed numbers-file paths and acquisition dates appear in footnotes instead
of duplicating the source in the main header.

Acquisitions are ordered by date then collection/expno. Residue rows span every
integer from the first observed residue to the last observed residue in that
condition, including wholly unassigned positions. They do not begin at 1 or
extend beyond the observed endpoints. Missing values stay blank with missing;
invalid fits have blank value/error and invalid_fit. Overlap values remain
visible. Multiple peak rows for one residue, or a known duplicate with an
unmatched companion, have blank value/error and multiple_peaks. No peak is
chosen, matched by proximity or averaged. Values/errors retain their exact
saved numerical precision.

NOISE AND ERROR LABELS

Noise percentages are 100 x each plane's saved noise SD / median absolute
first-plane peak height. The median uses unique, valid, non-overlapping peaks,
excluding zeros and nonfinite heights; its value and peak count are printed.
For HetNOE the first plane is the reference spectrum. For decays it is the first
ACQUIRED plane, even if omitted from the fit; it is not necessarily the shortest
delay. The percentages are an acquisition-level summary, not per-residue SNRs.
Unnormalised noise and individual heights remain in the detailed numbers file.

"all delays used" means the reported values come from the all-delay fit. It
therefore omits redundant exclusion=none and selection-reason text. Excluded
shortest delays are given directly in ms. No saved fit decision is changed.

error_adjusted_by_fitter replaces the overview's opaque uncertainty_rescaled
label. It means the reported parameter error was adjusted by the fitter using
residual scatter relative to the input noise. The fitted value is unchanged.
It does not cure poor model agreement or identify a mechanism. The original
warning, exact fitter factor and original-noise diagnostics remain in the
underlying reports; the overview does not perform or reverse any rescaling.
Equivalent original_noise_lack_of_fit / lack_of_fit flags are shown once.

Excluded acquisitions with known matching conditions are listed below the table.
The project-root condition-overviews.tsv is a generated delivery index including
excluded/pending dispositions, source-file links and user comments. Do not edit
that index for persistent assessments.

PERSISTENT USER REVIEWS

condition-reviews.tsv in the project root is EDITABLE INPUT. Normal regeneration
never rewrites it. It is created once with acquisition metadata and automatic
assessment snapshots alongside separate user fields:
    target, protein, experiment_type, pulse_program, acquisition_date,
    NaCl_mM, nominal_temperature_C, field_MHz,
    machine_disposition, machine_assessment, machine_reason,
    delays_used, fit_assessment,
    assessment, comment

The machine columns show the existing reviewed QC and condition evidence; they
are not user approvals and are not used as overrides. machine_disposition is
included, excluded or condition_review; machine_assessment identifies the saved
QC state (including review or not_assessed). Pending/provisional condition
qualifications remain explicit in machine_reason. Metadata values are catalog
snapshots, not new measurements or newly confirmed conditions.

Edit assessment and comment for your own decisions. They start blank. --user-reviews
PATH selects a different input. Old three-column target/assessment/comment files
remain accepted; extra/custom columns are allowed and ignored as decisions.
Use a collection/expno target for an acquisition, or a project-relative condition
directory (e.g. ANP32aIDR/25C/R1_500mM_600MHz) for a condition-wide note.

--update-review-context is an EXPLICIT opt-in to refresh the informational
columns or upgrade a three-column sheet. It preserves existing row order, user
assessment/comment values, custom columns and condition-wide notes; it appends
new acquisitions with blank user cells. Existing sheets are backed up and
replaced atomically, with a byte comparison to detect concurrent edits. Without
this flag, an existing review sheet is left byte-for-byte untouched. The script
never copies machine dispositions into the user's assessment column.
Assessment is blank (comment only), usable, review or exclude. An acquisition
assessment takes precedence over a condition-wide assessment; both comments are
retained. Explicit usable acceptance overrides acquisition exclusions, while the
automated QC evidence remains visible. review does not cancel an existing
exclusion. Neither an assessment nor a free-text comment silently changes salt,
temperature or other condition metadata; unresolved conditions stay pending until
the reviewed condition catalog is updated. The script reads the review input
without modifying it and propagates assessments/comments into the overview and
index. Tests verify that comments survive repeated generation.

REFRESH CONTRACT

--refresh-reports reads saved portable analyses from decay support ZIPs. It
validates them with relax_tools.py, reproduces the existing numerical cells,
and renders the PDF with the pulse sequence in its summary. Existing custom
HetNOE reports are plotted from their saved numbers; ratios/errors are not
recalculated and original list pairing/positions are not revisited.

Numbers tables keep their original bytes; only a pulse_program footer is added
(or an unknown pulse footer is filled). Noise, intensities, rates, errors,
overlap flags, fit decisions and native fitter/extraction records are preserved.
All existing ZIP members are retained; derived report members receive the pulse
metadata, and report_refresh.json identifies this as a metadata-only refresh.
Original fitting-code provenance stays unchanged. Existing job output-checksum
fields are updated solely to preserve the frozen driver's resume contract; no
hashes are added to numbers files, overviews or new refresh metadata.

Each acquisition's numbers file, PDF, support archive and existing job/provenance
records are locked, staged and replaced as one transaction. Backups go under
.report-backups/condition-overview-<timestamp> before replacement; publication
failure rolls back the complete set. Inputs are compared byte-for-byte before
publication. A failure later in the batch retains earlier successful refreshes;
a rerun skips already refreshed reports and completes the remaining work.
Overviews and their index are backed up on replacement. Per-acquisition output
names and the existing three user-facing analysis outputs are preserved.

TESTING

    python3 -m unittest discover -s relax/tests -p test_condition_overview.py -v

Tests use temporary synthetic saved results and stub rendering. They cover
cross-condition/protein grouping, provisional metadata, QC dispositions,
multiple peaks, missing/invalid/overlapping values, signed NOEs, full precision,
continuous residue ranges, relative-noise summaries, persistent user reviews,
metadata quoting, original native bytes and fitting provenance, input changes,
render failures, rollback, idempotence, dry runs and the TSV/index layout.

VALIDATED PROJECT DELIVERY (2026-10-26)

The Electrostatics refresh covered 114 current reports. The delivery contains
44 condition overviews with 69 acquisitions, five reviewed late-FID-growth
exclusions, and 40 pending-condition entries (36 heTDR1 and four ANP32A).
The first delivery had 4,522 observed-residue rows and 7,041 displayed value/error
pairs; 35 ambiguous cells were left blank. The revised layout also inserts rows
for unassigned residue positions between the observed endpoints. Independent before/after checks verified
identical numerical-table bytes, original native fit/extraction/input bytes,
original fitting provenance and all 114 saved acqus files. All 114 refreshed
PDFs contain their pulse-program name. The command ran with processing,
extraction and fitting executables unavailable in PATH. Representative decay
and NOE PDF pages and the grouped TSVs were inspected.
