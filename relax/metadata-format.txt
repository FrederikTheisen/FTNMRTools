Peak-list noise metadata

Three comments follow the final peak; the column header and peak rows stay intact:

# noise_sd: 29881.358701383433
# noise_method: MAD
# spectrum_scale: 1.0

noise_sd is in the same scaled intensity units as peak heights. MAD denotes
Gaussian-equivalent SD: median(abs(x-median(x))) / 0.6744897501960817.
The reproducible sample uses at most 65,536 points in 1D/2D, or 10,000 in nD.

Only when NOISE_REGION is explicitly configured, a fourth comment records it:
# noise_region: {"H":[9.0,9.5]}
Unspecified axes use their full range. Without this line, sampling spans the
whole spectrum. No JSON envelope, IDs, paths, hashes or diagnostics are exported.

Automatic sampling assumes most points are background. Grid noise is a proxy
for interpolated peak-height error: processing correlates neighbouring points.
Local artefacts, overlap, placement and systematic errors are not quantified.
Higher-dimensional noise is pooled, rather than estimated separately per plane.

hetnoe_analyze.py reads each spectrum's noise SD automatically and propagates
independent REF and NOE errors. Automatic metadata use requires matching
spectrum scales. The existing -noise option overrides both with a shared SD.
For plain files with neither metadata nor -noise, the zero-noise default
applies. Incomplete or invalid compact metadata stops automatic use.

relax_analyze.com strips comment lines for data_xtr and its overlap map;
per-plane vEstNoise.txt inputs remain in use for relaxation fits. Importers
and other readers should ignore lines starting with #.
The existing FTNMRTools strongest-intensity duplicate-residue policy is
unchanged; the separate 85-row ANP32A analysis keeps both E174 assignments.
